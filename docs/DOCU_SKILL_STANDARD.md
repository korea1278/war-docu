## A. 제작 과정 (대본 쪽)

### 1. 리서치 먼저 — `episodes/<ep>/research.md` (대본 쓰기 전에)
레퍼런스: 대본 전에 '연표 + 번호 붙은 출처' 브리프를 만들고, 출처끼리 숫자가 다르면 감추지 않고 표시함.
```
# <ep> 리서치 브리프
## 연표
| 날짜 | 사건 | 장소 | 숫자 | 출처 |
|---|---|---|---|---|
| 1950. 8. 3 새벽 | 고사리 매복 | 진동리 서쪽 | 사살 87 | [1][3] |

## 출처
[1] 국방부 군사편찬연구소 『6·25전쟁사』 5권 — https://... (2026-11-26 확인)
[2] ...

## 숫자 충돌
- 적 사살: [1] 87명 / [4] 80여 명 → 대본: "87명(한국 측 기록)" · 설명글에 두 기록 병기
- (충돌이 없으면 "없음" 한 줄)

## 앵글 후보 (갈등형·숫자형·질문형)
```
- 웹 검색으로 실제 출처를 열어 확인한 것만 [번호]로 올린다. 기억으로 쓴 숫자 금지
- '숫자 충돌'은 대본·화면·설명글에서 어떻게 표현할지까지 적는다 (예: 병기, '약', '기록마다 다름')
- 확인 못 한 것은 지금처럼 `unverified_facts.md`로 → 전달 때 알림

### 2. 비트 시트 — 장면 `src` + `pipeline/plan_sheet.py <ep>` → `beats.md`
레퍼런스: 대본을 비트로 나누고 비트마다 [나레이션 | 화면 | 출처] 3칸.
- 스토리보드 장면에 `"src": [1, 3]` (research.md 번호). **숫자가 들어간 문장은 src 필수** — 없으면 plan_sheet가 ⚠️
- `beats.md` = 장면 | 시각 | 나레이션(자막) | 화면 요약 | 출처. 미리보기 전에 이 표로 한 번 훑는다 (화면 종류가 3장면 넘게 같은지, 숫자 출처 빠진 곳)
- 렌더·API 0원, 세션에서 바로 실행

### 3. 목소리 ↔ 대본 대조 — `pipeline/asr_check.py <ep>` → `logs/asr_check_<ep>.txt`
레퍼런스: 만든 목소리를 받아쓰기해서 대본과 다른 두 단어를 잡아냄.
- 막 통 MP3를 무료 받아쓰기(Whisper large-v3-turbo · sherpa-onnx · 모델은 GitHub 릴리스, 약 1GB)로 듣고 대본과 글자 비교
- 자막 표기(t)와 읽는 말(say) **둘 다와 다른 곳 중 3글자 이상**만 '확인 필요'로 — 한두 글자 오인식(진동리→진동의)은 무시
- 종류: **빠짐**(TTS가 말을 건너뜀) · **덧붙음**(되풀이·헛말) · **바뀜**. 빠짐·덧붙음은 `logs/errors.txt`에도 남김
- Actions: **미리보기(mode=preview) 때만 자동 실행**, 경고만(렌더 안 멈춤), 20분 편 약 3~5분. 본 렌더는 시간 한도(340분)에 가까워 생략
- 미리보기 확인 때 이 파일도 같이 연다 → 진짜 틀렸으면 귀로 확인 후 그 막만 다시 생성
- 실측(EP34 act0·act3): 글자 일치율 98.2%, 오탐 0 · 일부러 넣은 빠짐 '끝없이 계속' 정확히 잡음

### 4. 자료 체크리스트 — 장면 `need` + `plan_sheet.py` → `assets.md`
레퍼런스: 실제 사진·기사·영상처럼 AI가 못 만드는 것을 '필수/선택 · 없으면 대체' 표로 사용자에게 요청.
- 사진(핀 유무 — 핀 없으면 ⚠️), 재연 그림(재사용 0원 / 새로 그림), **사용자 제공 자료** 한 표
- 사용자가 구해 줘야 하는 자료는 장면에 `"need": {"what": "1982. 5. 4 더 선 1면 캡처", "required": false, "fallback": "document 카드로 요점만"}`
- 사용자에게 요청할 때는 assets.md의 '사용자 제공' 줄만 뽑아 보여 준다 (PC방이라 파일 첨부로 받음 → `public/ep/<ep>/user/`)

## B. 화면 (remotion/DocuKit.tsx · MapView `ring` · ui.tsx `clip.recreated`)

### 5. 지구본 원정 비행 `visual.type: "globe"`
```json
{"type": "globe", "from": [-2, 38], "to": [14, 42],
 "route": [[-0.98, 37.6], [7.0, 45.1], [16.13, 41.3]], "on": "알프스를 넘어", "dur": 4,
 "pins": [{"ll": [-0.98, 37.6], "text": "카르타고 노바"}, {"ll": [16.13, 41.3], "text": "칸나이", "on": "칸나이"}],
 "fill": {"380": "#d9a441"},
 "counter": {"to": 1600, "unit": "km", "label": "한니발이 걸은 거리 (약)"},
 "zoom": {"to": 2.4, "on": "이탈리아", "dur": 1.6}}
```
- 지구가 from→to로 돌며 대권 항로(노란 점선)가 그려지고 오른쪽 판의 숫자가 같이 올라감. `fill`은 world-atlas ISO 숫자 코드
- 쓰는 곳: 원정·파병·해상 수송 거리(격전의 세계사: 페르시아 원정, 나폴레옹 러시아 원정, 몽골 / 격전의 지도: 16개국 파병, 영연방·에티오피아 파병 거리)
- 지역이 좁으면 `zoom`으로 파고든 뒤 다음 장면을 그 지역 지도로 이어 받는다

### 6. 사진 위 카운터 + 도장 (어느 화면에나) `visual.counters` · `visual.stamp`
```json
"counters": [{"from": 0, "to": 3, "fmt": "clock", "unit": "시간", "label": "버틴 시간", "on": "세 시간", "dur": 2.5},
             {"to": 3000, "unit": "명", "label": "상륙 병력 (약)", "on": "삼천"}],
"stamp": {"text": "항복", "on": "항복", "x": 0.5, "y": 0.42, "rot": -8}
```
- 오른쪽 위 짙은 유리판(노란 윗줄)에 숫자가 올라감 (`fmt: "clock"`은 시간 → H:MM). `counterPos: "left"`, `counterTop`
- 도장은 크게 쾅 → 제자리 (붉은 이중 테두리). document 카드의 문자열 `stamp`와는 별개(객체일 때만)
- 숫자는 research.md 출처가 있는 것만 · 사진 위 사람 얼굴을 가리지 않게 x·y 조정

### 7. 무기 실루엣 도해 `visual.type: "weapon"`
```json
{"type": "weapon", "bg": "sea",
 "units": [{"kind": "sub", "x": 0.3, "y": 0.62, "w": 640, "label": "잠수함 컨커러", "sub": "영국 해군 핵잠수함"},
           {"kind": "ship", "x": 0.82, "y": 0.64, "w": 520, "flip": true, "label": "벨그라노", "on": "벨그라노"}],
 "shots": [{"from": 0, "to": [0.72, 0.6], "n": 3, "kind": "torpedo", "on": "어뢰", "dur": 2.2}],
 "count": {"text": "어뢰 3발", "on": "세 발"}}
```
- kind: `sub` 잠수함 · `ship` 군함 · `carrier` 항모 · `jet` 제트기 · `plane` 프로펠러기 · `tank` 전차 · `galley` 갤리선(노 움직임) · `cannon` 대포 · `missile` 미사일
- shots kind: `torpedo`(점선 꼬리) · `missile`(불꽃·연기) · `arrow`(포물선 화살) · `shell`(포탄). `from`은 유닛 번호(기수에서 발사) 또는 [x,y], `hit:false`면 명중 섬광 없음
- 유닛 `move: {to:[x,y], dur, at|on}`로 날아 들어오기. bg: `blueprint`(기본, 설계도 격자) · `sea` · `sky`
- 실루엣은 직접 그린 단순 도형(저작권 없음). 실제 모양 비교가 중요한 장면은 사료 사진을 쓴다

### 8. 지도 구역 원 `items: {"k": "ring", ...}` + 도장
```json
{"k": "ring", "p": [-57.8, -51.7], "km": 370, "text": "200해리 배제 구역", "on": "배제 구역"}
```
- 반지름 km로 원이 커지며 점선이 천천히 돈다 (기본 노랑, `color`). 격침 지점은 `marker`·`badge`, '아직도 논쟁 중' 같은 결론은 장면 `visual.stamp`
- 쓰는 곳: 배제 구역·사거리·포위망·보급 한계선

### 9. 초단타 반전 카드 `visual.type: "punch"`
```json
{"type": "punch", "text": "틀렸습니다.", "sub": "영국은 함대를 보냈습니다"}
```
- 검은 화면 한 줄 + 노란 밑줄이 그어짐 (`color: "red"` 가능). 1~2초짜리 한 문장 장면에만
- 글자 카드로 집계됨(card_max 25%) — **한 편에 2~4번**, 통념이 뒤집히는 순간(후킹 X 마크 다음, 막 전환점)에만

### (덤) 인용 카드 '원문 재구성' 표시 — `clip.recreated: true`
- 외국 사료를 우리말로 옮기거나 문장을 다시 짠 인용 카드는 카드 아래 작게 "※ 원문을 옮겨 다시 구성" (문자열을 주면 그 문구)

## C. 제작 순서에 끼워 넣는 위치
1. 소재 확정 → **research.md** (연표·출처·숫자 충돌·앵글 후보) → 대본
2. 스토리보드에 `src`·`need` → **`python3 pipeline/plan_sheet.py <ep>`** → beats.md·assets.md 확인 (⚠️ 0개 목표, 사용자 제공 자료가 있으면 이때 한 번에 요청)
3. 미리보기 → 시트 + **`logs/asr_check_<ep>.txt`** 같이 확인
4. 전달 때 research.md의 '숫자 충돌'을 설명글 출처 표기에 그대로 반영
- 화면 비율 기준(지도 60%↑·글자 카드 25%↓)은 그대로. globe·weapon은 지도·카드 어느 쪽에도 안 세지만 **한 편에 각 3~6장면** 정도로 — 늘 지도가 주인공
- 렌더 확인: `zz-docukit` 같은 임시 에피소드에 기존 timeline.json을 복사해 장면 visual만 바꾸고 `npx remotion still`로 (커밋 금지)
